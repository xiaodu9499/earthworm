# Earthworm Web 设计与发布回归规范

> 适用范围：`apps/website` 的练习、课程、响应式布局、语音、认证同步、管理后台与生产发布。
>
> 核心原则：完成标准是“用户在目标设备上完成真实学习任务”，不是代码能编译、页面返回 HTTP 200、DOM 中存在按钮或自动化能找到元素。

本规范来自 2026-08-22 至 2026-08-23 的连续改造和真机反馈。每次修改练习、课程、登录同步或响应式布局，都应验证从进入课程、输入、提交、结果反馈、下一题或下一课、语音，到进度同步的完整链路。

## 1. 已确认的坑与防回归规则

### 1.1 DOM 有按钮不代表用户看得到

- **症状**：最后一题完成后，DOM 已生成“开始下一课”，但真机页面没有按钮。
- **根因**：电脑版在窄屏下给练习区设置 `height: 100%`，同时顶部仍有页头与工具栏；按钮被排到可视区域之外，又被外层 `overflow: hidden` 裁掉。
- **规则**：页面使用纵向 flex/grid 分配剩余高度，关键子项统一考虑 `min-height: 0`；底部操作考虑 `env(safe-area-inset-bottom)`。不要在嵌套容器中混用 `100vh`、`100dvh`、`100%` 后再靠 overflow 掩盖问题。
- **验证**：读取按钮 `getBoundingClientRect()`，必须满足 `top >= 0 && bottom <= innerHeight`；随后真正点击并确认进入下一课。

### 1.2 手机设备可能仍在访问电脑版路由

- **症状**：用户反馈“手机端缺按钮”，但截图顶部显示 `PC` 和“切换手机版”。
- **根因**：设备类型与页面路由不是同一个概念；用户可能手动切换过版本、从旧链接进入，或缓存了 `/desktop`。
- **规则**：手机专用 `/mobile` 和手机窄屏访问 `/desktop` 都必须具备可用的兜底布局。排障时先识别实际路由、视口和页面标识，不要仅根据“手机端”猜测组件。
- **验证**：至少覆盖 `/mobile` 手机视口和 `/desktop` 手机窄屏两条路径。

### 1.3 iOS 键盘必须在原始触摸手势内聚焦可编辑控件

- **症状**：输入框显示选中状态或光标，但 iPhone、微信内置浏览器不弹出系统键盘。
- **根因**：未激活单词槽位处于 `readOnly`；旧逻辑先 focus，再等待 React 状态更新解除只读。iOS 不会在异步状态更新后补弹键盘，`requestAnimationFrame`、`setTimeout` 和 `autoFocus` 都不能替代真实手势。
- **规则**：在 `pointerdown` 或 `touchstart` 的同一次用户手势内，同步解除目标输入框只读、切换当前单词并 focus；其他槽位恢复只读。移动练习页不要依赖进入页面后的自动聚焦。
- **验证**：触摸后目标应立即满足 `readOnly=false`、`tabIndex=0`、`document.activeElement === input`；最后仍需实体 iPhone 验证键盘实际出现。

### 1.4 软键盘适配必须使用 visualViewport

- **症状**：键盘弹出后卡片位置错乱、按钮重叠、出现大片空白或页面整体跳动。
- **根因**：布局只读取 layout viewport 或 `100vh`，没有感知 iOS 键盘改变后的可见高度和 offset；同时 body、内部滚动区和绝对定位操作栏竞争滚动。
- **规则**：以 `visualViewport.height` 和 `visualViewport.offsetTop` 计算键盘态；练习页约束在可见视口内；只保留一个明确的内部滚动容器。键盘态压缩非核心信息，优先保留题目、当前输入和提交操作。
- **验证**：键盘开合前后无横向滚动，目标卡片不被键盘遮挡，焦点不丢失，关闭键盘后布局恢复。

### 1.5 Space 和 Enter 必须接管浏览器默认行为

- **症状**：按空格提交时页面闪动、滚动或看起来像刷新；快速按键可能跳词、重复完成；Enter 在结果页没有进入下一题。
- **根因**：Space 的页面滚动默认行为、`beforeinput` 与 `keydown` 双路径、输入法 composition、按键 repeat 和 React 重渲染同时发生。
- **规则**：提交键同时执行 `preventDefault()` 与 `stopPropagation()`；处理 `beforeinput` 的空白输入；忽略 `isComposing` 和 `repeat`；使用一次性提交闸避免同一帧重复提交。结果态 Enter 映射到下一题，课程末题映射到下一课或课程目录。
- **验证**：覆盖连续输入、空格提交、长按、中文输入法组合态和最后一题，确保不刷新、不滚页、不重复跳题。

### 1.6 输入槽位稳定不能以牺牲手机键盘为代价

- **症状**：为了避免答案展示时页面闪动，把所有单词都渲染为输入框并用 `readOnly` 区分，随后引入键盘无法弹出的回归；宽度还可能随输入值变化。
- **根因**：视觉稳定、焦点管理和浏览器键盘限制被分开处理。
- **规则**：槽位宽度由目标单词和 CSS 变量稳定计算，不随当前输入值抖动；保留明确的唯一活动槽位；任何只读切换都必须符合“同一触摸手势内解除只读并聚焦”的规则。
- **验证**：长短单词、换行、多行句子、输入态与结果态切换时布局不闪，当前输入仍能立即唤起键盘。

### 1.7 下一题、下一课和课程结束必须是不同状态

- **症状**：普通结果页缺少“下一题”；课程最后一题仍显示禁用的“下一题”；完成课程后没有继续入口。
- **根因**：只用 `canNext` 一个布尔值表达题目边界，没有把“当前题是否已回答”和“是否存在下一课”组合成完整状态机。
- **规则**：活动题、已回答且有下一题、已回答且有下一课、全部课程结束、复习列表结束分别处理。最后一题显示“开始下一课”；没有下一课或复习结束显示“返回课程目录”。键盘 Enter 与按钮行为保持一致。
- **验证**：实际点击每个出口并确认课程 ID 或题号变化，不能只断言按钮文本存在。

### 1.8 答案比较与语音文本不能直接复用原始字符串

- **症状**：中文“我”的答案是 `I`，用户输入后无法通过；单独 `I` 的语音可能被当作字母或罗马数字误读。
- **根因**：输入法可能产生全角 `Ｉ`，简单 lowercase 不会统一；浏览器 TTS 对孤立 `I` 存在歧义。
- **规则**：答案比较先执行 Unicode NFKC、英文 locale 小写和标点清理；孤立代词 `I` 的朗读文本明确映射为 `eye`，并优先选择英语语音。课程原始数据、答案归一化和朗读适配应分层定位。
- **验证**：半角 `I`、全角 `Ｉ` 都能通过；单词按钮和整句朗读无运行错误，并在实体设备试听最终发音。

### 1.9 单词卡点击的产品动作应保持单一

- **症状**：点击单词既展开解释又朗读，界面层级和用户预期发生冲突。
- **根因**：把“查看更多信息”和“立即获得发音反馈”绑定在同一个动作上。
- **规则**：单词解释常驻卡片内，点击单词直接朗读；句子解析使用独立按钮。不要在核心练习中通过点击单词制造额外布局变化。
- **验证**：每个单词可独立点击朗读，卡片高度不因此改变，键盘焦点和当前题状态不受影响。

### 1.10 响应式不能依靠重复 media query 逐层打补丁

- **症状**：前面设置正确的 `calc()` 高度，被文件后部同选择器的 `height: 100%` 静默覆盖；普通桌面测试通过，手机窄屏失败。
- **根因**：同一组件的响应式规则散落在多个 `@media` 段，CSS 级联顺序成为隐藏状态机。
- **规则**：同一断点的规则集中；页面框架负责可用高度，练习组件只消费剩余空间。修改后检查最终 computed style，而不是只读取靠前的源码规则。
- **验证**：同时记录 viewport、document/body scrollHeight、关键容器 rect、computed height 和 overflow。

### 1.11 登录同步不能只验证“能登录”

- **症状**：登录后课程进度能恢复，但“不熟悉”单词可能丢失；首次登录还可能覆盖本机已有记录。
- **根因**：把同步当成单一进度字段，没有定义首次合并、冲突方向和多类学习状态。
- **规则**：账号首次使用可自动创建，但合并时保留本机题号、“不熟悉”和“已掌握”标记，再与云端合并；后续写入统一走账户级状态。未登录仍可继续本机学习。
- **验证**：未登录制造进度和标记，首次登录后刷新或换设备，两类数据都应存在，且同步状态明确。

### 1.12 密码重置必须验证完整邮件链路

- **症状**：收到重置邮件，但链接回到 `/mobile` 或提示无效、过期，没有进入新密码页面。
- **根因**：发送来源是 localhost、`redirectTo` 与 Supabase Site URL 或允许回调列表不一致，或者链接已过期、被消费。页面存在和邮件发送成功都不是完成。
- **规则**：生产站发送时显式使用生产 `/reset-password`；Supabase 同时配置 Site URL 和允许回调；页面恢复 recovery session 后才能提交新密码。
- **验证**：生产站发信，点击最新邮件，建立恢复会话，修改密码，使用新密码登录，并确认学习数据仍在。

### 1.13 邮箱验证码取决于服务端模板

- **症状**：前端显示“发送验证码”，邮件中却只有 magic link，没有数字验证码。
- **根因**：Supabase 邮件模板没有输出 token；前端无法让服务端邮件凭空出现 OTP。
- **规则**：如果采用邮箱密码，应明确使用密码登录和密码恢复；如果采用 OTP，先确认模板、SMTP、频率限制和大陆可达性，再实现前端输入框。不要让 UI 文案领先于可用的认证链路。

### 1.14 管理入口不能通过前端硬编码管理员邮箱授权

- **症状**：PC 端需要管理员入口和用户进度统计，容易直接在前端比较某个邮箱地址。
- **根因**：前端条件只能控制按钮是否可见，不能保护数据接口；用户仍可直接访问路由或调用数据库。
- **规则**：入口可以按登录身份显示，但 `/admin` 数据必须由服务端或 Supabase 权限与 RLS/RPC 授权；管理页面默认只读；数据库拒绝普通用户直接读取全量学习记录。
- **验证**：管理员可见且可读，普通用户直接访问路由和 API 均失败，不能只测试按钮隐藏。

### 1.15 Vercel 发布成功不等于中国大陆稳定可用

- **症状**：绑定国内域名后仍然存在大陆访问问题，误以为域名能够改变 Vercel 节点和网络可达性。
- **根因**：域名、DNS、CDN/源站、Supabase、邮件和 TTS 是不同链路；国内域名不会把 Vercel 自动迁入大陆。香港节点也只能改善部分网络路径，不能保证所有地区稳定。
- **规则**：大陆可用性要逐项选择大陆或港澳可达的托管、数据库、邮件和音频依赖；如果使用中国大陆节点，需要评估域名实名认证、备案和合规要求。外部 TTS 必须具备浏览器本地语音或可达的备用路径。

### 1.16 没有服务端日志不等于“零错误”

- **症状**：Vercel `logs` 返回 `No logs found`，容易误报为“服务端零错误”。
- **根因**：静态导出页面可能根本没有函数日志，这只代表没有观测数据。
- **规则**：区分“没有日志条目”和“扫描到零条错误”；前端运行错误查看浏览器 console，业务正确性依赖实际交互，HTTP 200 只证明资源可访问。

### 1.17 发布后必须考虑手机 WebView 缓存

- **症状**：正式环境已经更新，手机 Safari 或微信仍然表现为旧 bug。
- **根因**：移动 WebView 可能继续使用旧 JS/CSS 资源，或者保留旧标签页状态。
- **规则**：每次发布先验证 production alias 指向新 deployment；真机复测时关闭旧页面重新打开，必要时清理 WebView 缓存。不能因为自动化的新标签页通过，就否定用户旧标签中的现象。

## 2. 发布回归门槛

每次涉及练习、课程、布局、语音或账号数据的修改，至少完成以下检查：

1. 运行项目现有的 lint、TypeScript、生产构建和 `git diff --check`。
2. 验证 Desktop `1440×900`、Laptop `1280×720`、Tablet `768×1024`、Mobile `390×844`、Small Mobile `375×812`。
3. 额外验证手机窄屏打开 `/desktop` 的兜底路径。
4. 确认页面没有意外横向滚动；记录 document/body 高度、关键容器 rect 和 overflow。
5. 确认输入框触摸后立即可编辑并保持焦点；使用实体 iPhone 或微信验证软键盘。
6. 确认 Space 完成单词时不滚页、不闪烁、不重复提交；Enter 在结果态进入正确出口。
7. 实际点击并验证普通下一题、课程最后一题、下一课、全部完成、复习结束五类边界。
8. 分别验证单词朗读、整句自动朗读和答题后朗读；自动化无法听声音时，必须明确保留真机试听门槛。
9. 分别验证未登录本地进度、首次登录合并、跨设备同步、“不熟悉”和“已掌握”标记。
10. 发布到 preview 或 production 后，使用生产 alias 重跑关键路径，并记录 deployment ID、HTTP 状态、浏览器错误和缺失的观测能力。

## 3. 规范过期条件

当 Earthworm Web 不再使用当前 React/Next 前端、浏览器语音、Supabase 登录同步，或练习交互不再是“逐词输入/拆句重组”时，应重新评审对应小节。

无论技术栈如何变化，“以真实任务链而非构建成功作为完成标准”仍然保留。
